# Conventions

## Source of truth

The spec describes the code on `main` at the commit a chapter names.
Prose in this book never outranks the code: when they differ, the
code is right and the chapter is wrong, and the fix is a change here
with the issue that tracks the divergence. Chapters are written by
reading the source, the models and the tests, not from memory of
earlier prose.

## Chapter skeleton

Every protocol chapter uses these sections, in this order:

1. **Goal**: what the protocol achieves for whom.
2. **Actors**: the parties and the attacker.
3. **Message flow**: the messages in order, with a diagram.
4. **Normative operations**: the cryptographic steps, with MUST and
   SHOULD, each naming the source file and function.
5. **State machine**: states, transitions, what each side persists.
6. **Failure cases**: every way the protocol stops, and what the user
   is told.
7. **Security considerations**: what holds, what does not, and the
   claims (S-numbers) this chapter backs.
8. **Vectors**: which entries of the vectors file exercise it.

## Requirement words

MUST, MUST NOT, SHOULD and MAY are used as in RFC 2119, and they
describe the shipped code. A MUST the code violates is a defect and
gets an issue, not a softened sentence.

## Claims

Claims are numbered S1, S2, ... and never renumbered; a withdrawn claim
keeps its number and says it was withdrawn. Each claim carries:

- **Attacker**: who is assumed and what they control.
- **Statement**: one sentence, falsifiable.
- **If false**: what breaks for a user.
- **Status**: *shipped* (code on `main`, proof in CI), *partial* (the
  mechanism exists, the proof or part of the behaviour is missing, and
  the entry says which), or *planned* (a tracked gap, not a claim).
- **Backed by**: the test function, lemma or certification lane, by
  name, and the normative section.

## Versioning

The book is tagged `MAJOR.MINOR[-draft]`. A tag is immutable; a
correction is a new tag. Spec versions are independent of app and Core
versions; the changelog maps each spec tag to the Core commit it was
extracted from. Wire-format changes bump MINOR while the spec is a
draft and MAJOR afterwards.

## Machine-readable artefacts

A machine-readable file (vectors, transcripts, schemas) is added only
together with the check that fails when it and the code disagree.
Today: the vectors are generated by Core's test suite and compared by
CI. Schemas will follow the same rule (ADR-076).

## Scope

The spec covers the personal layer: one person, their devices, their
contacts. Organisation identities are an extension point and are
marked as such where a protocol would have to change.
